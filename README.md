### Neuro — MVP1

Система совместного анализа логов с LLM. Pure Python (FastAPI + SSR + HTMX).

### Запуск в PyCharm
1. Откройте папку `neuro-mvp1` как проект.
2. Создайте и активируйте виртуальное окружение:
   - Windows: `python -m venv .venv && .venv\Scripts\activate`
   - macOS/Linux: `python -m venv .venv && source .venv/bin/activate`
3. Установите зависимости: `pip install -r requirements.txt`
4. Скопируйте `.env.example` → `.env`, сгенерируйте `SECRET_KEY`:
   `openssl rand -hex 32`
5. Запустите: `uvicorn main:app --reload`
6. для запуска по локальной сети - `uvicorn main:app --host 0.0.0.0 --port 8000 --reload`
7. Откройте http://127.0.0.1:8000

## Где что лежит

 Проект разделен на логические блоки: настройки, база данных, обработчики страниц (роутеры), бизнес-логика (сервисы) и внешний вид (шаблоны).

### Корень проекта (настройки и запуск)
*   **`main.py`** — Точка входа. Здесь создается приложение, подключаются все страницы и создается админ по умолчанию.
*   **`config.py`** — Чтение настроек из файла `.env` (секретные ключи, лимиты файлов и т.д.).
*   **`database.py`** — Подключение к базе данных SQLite. Здесь же функция `get_db()`, которая выдает доступ к БД.
*   **`models.py`** — **Главный файл для структуры БД**. Здесь описаны все таблицы (Пользователи, Чаты, Сообщения, Настройки).
*   **`schemas.py`** — Правила валидации форм (какой длины должен быть пароль, сколько символов в сообщении и т.д.).
*   **`requirements.txt`** — Список библиотек для установки.

### Папка `routers/` (Обработчики адресов)
Здесь лежат файлы, которые отвечают на запросы браузера (открытие страниц, нажатие кнопок).
*   **`auth.py`** — Вход (`/login`) и выход (`/logout`).
*   **`chats.py`** — Вся работа с чатами: главная страница, создание, отправка сообщений, поиск, удаление. *(Самый большой файл)*.
*   **`files.py`** — Загрузка файлов в чат.
*   **`settings.py`** — Страница настроек API нейросети (доступна только админу).

### Папка `services/` (Бизнес-логика)
Здесь лежит «тяжелая» логика, которую роутеры просто вызывают.
*   **`auth_service.py`** — Проверка паролей, создание JWT-токенов, проверка сессий.
*   **`llm_service.py`** — **Работа с нейросетью**. Сборка промпта, отправка запроса, получение ответа.
*   **`file_service.py`** — Обработка файлов: проверка расширений, нарезка на куски (чанки) и сохранение в ChromaDB (векторная база для RAG).

### Папка `middleware/`
*   **`session_activity.py`** — Следит за тем, чтобы сессия пользователя продлевалась, пока он активно пользуется сайтом (чтобы не выкинуло через 30 минут).

### Папка `templates/` (HTML-страницы)
*   **`base.html`** — **Главный каркас**. В нем лежит сайдбар (боковое меню), шапка и подключение HTMX/Tailwind. Все остальные страницы вставляются внутрь него.
*   **`login.html`** — Страница входа.
*   **`index.html`** — Главная страница (заглушка, если нет чатов).
*   **`chat.html`** — Окно чата (лента сообщений и форма ввода).
*   **`settings.html`** — Форма настроек API для админа.
*   **`components/`** — Мелкие кусочки страниц:
    *   `chat_list.html` — список чатов в сайдбаре.
    *   `message.html` — отображение одного сообщения в ленте.
    *   `banner.html` — желтая плашка «Сервис недоступен».
    *   `modal_confirm.html` — всплывающее окно подтверждения удаления.

## Инструкция по командной работе в GitHub (через интерфейс PyCharm)

Чтобы мы не теряли код, не ломали рабочие функции и не мешали друг другу, мы работаем по следующим правилам. Пожалуйста, прочитайте их перед началом работы.

### Основные правила
1. **Ветка `master` защищена.** Никто не пушит в неё напрямую. Все изменения — только через Pull Request (PR).
2. **Одна задача = одна ветка.** Не делайте одну ветку на всю неделю.
3. **Перед началом работы всегда обновляйте `master`.**
4. **Перед созданием PR обновляйте свою ветку из `master`**, чтобы избежать конфликтов.
5. **PR должен получить **1 одобрение (Approve)** от коллеги.

---

### Пошаговый алгоритм

#### Шаг 1. Начало новой задачи (обновление и создание ветки)
1. Убедитесь, что находитесь в ветке `master`. Если нет — нажмите на название текущей ветки и выберите `master` → `Checkout`.
2. В верхнем меню нажмите **Git** → **Pull...** (или нажмите синюю стрелочку вниз на верхней панели). В появившемся окне нажмите **Pull**. Это заберет свежие изменения с GitHub.
3. В правом нижнем углу снова нажмите на название ветки (`master`).
4. В появившемся меню выберите **New Branch**.
5. Введите название ветки на английском, без пробелов (например, `feature/export-chat` или `feature/notifications`).
6. Убедитесь, что стоит галочка **Checkout branch**, и нажмите **Create**. Вы автоматически переключитесь на новую ветку.

#### Шаг 2. Работа над задачей и сохранение (коммит)
1. Пишите код, проверяйте его локально.
2. Когда сделали логический кусок, в верхнем меню нажмите **Git** → **Commit...**
3. В левой части окна отметьте галочками файлы, которые хотите сохранить (обычно это все измененные файлы).
4. В поле **Commit Message** напишите понятное описание. Шаблон: `feat: краткое описание` или `fix: краткое описание`. Пример: `feat: добавлен экспорт в txt`.
5. Нажмите кнопку **Commit** (синяя кнопка внизу окна).

#### Шаг 3. Отправка ветки на GitHub (Push)
1. В верхнем меню нажмите **Git** → **Push...**
2. В появившемся окне вы увидите вашу ветку и ваши коммиты. Нажмите кнопку **Push** в правом нижнем углу.

#### Шаг 4. Создание Pull Request (PR)
1. Зайдите на сайт GitHub в наш репозиторий.
2. Нажмите зеленую кнопку **"Compare & pull request"** (она появится рядом с вашей веткой) или перейдите во вкладку **Pull requests** → **New pull request**.
3. В поле **base** выберите `master`, в поле **compare** — вашу ветку.
4. Заполните **Title** и обязательно **Description**:
   * *Что сделано:* (список изменений)
5. Справа выберите **Reviewer** (Назначайте Алексея(Kadaurs)) и назначьте себя в **Assignees**.
6. Нажмите **Create pull request**.

#### Шаг 5. Что делать, если `master` ушел вперед (конфликты)
Если пока вы работали, кто-то уже влил свой код в `master`, перед мержем вашего PR нужно обновить вашу ветку.
1. Убедитесь, что вы находитесь в своей ветке (в правом нижнем углу PyCharm написано её название).
2. В верхнем меню нажмите **Git** → **Fetch...**. Это скачает информацию о новых изменениях, но не применит их.
3. В правом нижнем углу нажмите на название вашей ветки → выберите **Merge 'origin/master' into 'ваша-ветка'**.
4. Если конфликтов нет, PyCharm просто смержит код и покажет уведомление. Если конфликты есть — PyCharm откроет окно с тремя панелями. В центральной панели выберите нужные куски кода (нажимая стрелочки `>>` или `<<`), чтобы оставить оба варианта, и нажмите **Apply**.
5. После разрешения конфликта снова сделайте **Commit** (Шаг 2) и **Push** (Шаг 3).

#### Шаг 6. Ревью и слияние (Мерж)
* **Автор PR:** Ждет, пока назначенный ревьюер проверит код.
* **Ревьюер:** Заходит в PR на GitHub → вкладка **Files changed** → читает код. Если всё ок, нажимает **Review changes** → **Approve**. Если есть замечания — **Request changes** (тогда автор их исправляет, снова делает Commit и Push в ту же ветку).
* **После одобрения:** Нажмите зеленую кнопку **Merge pull request** → **Confirm merge**.
* **После мержа:** GitHub предложит удалить ветку — нажмите **Delete branch** (история коммитов останется в `master`, а ветка больше не нужна).

## 🏷️ Правила разметки интерфейса для автотестов (data-testid)

Чтобы наши автотесты работали стабильно и не падали из-за смены дизайна (например, если мы поменяем цвет кнопки или её текст), мы обязаны размечать все интерактивные элементы специальным атрибутом `data-testid`. Автотестер будет искать элементы на странице ТОЛЬКО по этому атрибуту.

### Главное правило
**Любой элемент, на который можно кликнуть, в который можно написать текст или который нужно проверить (например, сообщение об ошибке), ОБЯЗАТЕЛЬНО должен иметь атрибут `data-testid`.**

### Как и куда писать атрибут
Атрибут пишется внутри открывающего HTML-тега, как обычный атрибут (рядом с `class`, `id`, `name` и т.д.). 
Пример: `<button class="bg-blue-600" data-testid="btn-submit-login">Войти</button>`

### Формат именования (kebab-case)
*   Только латиница, цифры и дефисы. Никаких пробелов, кириллицы или заглавных букв.
*   Общий шаблон: `[тип-элемента]-[название]-[уточнение]`.
*   **Префиксы для типов элементов:**
    *   `btn-` — кнопки (button, a с ролью кнопки). Пример: `data-testid="btn-save-settings"`
    *   `input-` — поля ввода (input, textarea, select). Пример: `data-testid="input-user-email"`
    *   `link-` — ссылки навигации. Пример: `data-testid="link-go-home"`
    *   `modal-` — модальные окна. Пример: `data-testid="modal-delete-chat"`
    *   `msg-` — сообщения или текстовые блоки. Пример: `data-testid="msg-error-login"`
    *   `badge-` — счетчики и индикаторы. Пример: `data-testid="badge-unread-count"`
    *   `form-` — формы. Пример: `data-testid="form-login"`

### Если элементов несколько (списки, таблицы)
Если элемент повторяется в списке (например, сообщения в чате, промпты или участники), в конец названия ОБЯЗАТЕЛЬНО добавляется уникальный ID из базы данных.
*   Пример: `data-testid="btn-delete-prompt-15"` (где 15 — ID промпта).
*   Пример: `data-testid="msg-chat-42"` (где 42 — ID сообщения).
